Desktop DICOM viewer

Nefertiti

A desktop DICOM viewer for CT, MRI and X-ray images, made for private specialist clinics.

Created by Dr Amr Kazzaz

For reference only, not for diagnosis.

Nefertiti is not a medical device and has not been cleared or registered by any regulator, including the EDA in Egypt or the SFDA in Saudi Arabia. Clinical decisions must be made with approved systems and by qualified people.

What it is

Surgeons and specialists in private clinics — including orthopaedics and neurosurgery in Egypt and Saudi Arabia — often receive patient imaging on CDs and USB drives from radiology centres. They want to open those studies, look at them, measure, compare visits, and keep a private copy. Nefertiti is built for that desk.

It opens the CD or USB a patient brings, keeps a private encrypted library on the computer, and lets you view, measure and compare studies. It works offline: no network calls, no telemetry, no analytics and no update check. The original images are never changed; measurements and notes are stored with the study.

This repository holds installers only. The source code is proprietary and is not published. Nefertiti is an independent project. It does not contain Horos or OsiriX code, and it is not affiliated with either project.

Features

A short tour of what the app can do. Every measurement carries the sentence “for reference only, not for diagnosis”.

Viewing

  • Open DICOM studies from a disc, USB stick or folder (DICOMDIR when present, otherwise a scan of loose files). You can also drop a folder on the window or use the system’s Open With.
  • Window and level, including right-drag and the W key, with presets.
  • Zoom, pan and reset the view (measurements stay).
  • Rotate right, flip horizontal and flip vertical.
  • Scroll through a stack with the mouse wheel or the keyboard; play or pause cine on a multi-frame series.
  • Present mode shows the picture alone and hides names. Full screen is also available.
  • A command palette (Ctrl+K) lists commands by name. A short right-click opens a ring of choices.

Layouts, compare and follow-up

  • One, two or four images on screen (1, 2, 4).
  • Compare places two images side by side (1×2). Link scroll starts off; turn it on to move both. Shift-click marks the same spot on the other image.
  • Follow-up compare: open a patient, then choose two dated studies under Studies by date to compare an older visit with a newer one.
  • Mark or unmark a key image (I).

Measurements

  • Length, angle, Cobb angle, ellipse area, annotations, and a Calibrate tool.
  • Calibration is always stated. If the image has no usable scale, the length is shown in pixels as Uncalibrated — never as millimetres invented by the app.
  • On a plain X-ray the scale may be magnified, and the words “May be magnified” say so. Calibrate lets you set the scale from an object of known size.
  • A Cobb angle is the smaller angle, 0 to 90 degrees.
  • Measurements are as exact as the scan and the scale allow. They are for reference only, not for diagnosis, and are not for planning, sizing or choosing an implant or an operation.

Multiplanar views (MPR)

  • For a CT that can be a volume, View → MPR shows Axial, Coronal and Sagittal planes and a Volume pane.
  • One slanted (oblique) plane is available in the Volume pane: Turn spins it (−180 to 180 degrees), Slant tips it (up to 80 degrees either way), and Square puts it back on the axial plane. There is no curved plane.
  • A length or angle on a plane is the patient-space distance, in millimetres or degrees.
  • A tilted stack, or slices that are not evenly spaced, is not offered for planes; the 2D images still work. Many head CTs are like this.
  • Planes also need WebGL2. If this computer cannot create a volume view, the 2D stack remains available.
  • Nefertiti reconstructs 2D slices, orthogonal planes and a 3D view from a series that is already a stack of images. It does not reconstruct raw scanner data.

3D bone model

  • A bone surface can be built from a CT (not from MRI), after you choose a starting point and press Build model. Nothing is built until you ask.
  • The only numbers on the model are a distance, an angle, and the size of a piece’s box (length × width × height). It does not show the volume of a bone or of a piece.
  • Pieces can be shown, hidden, joined, removed, recoloured or split by two clicks. Points are clicked by hand; there is no automatic landmark and no AI.
  • A very large CT builds at lower detail only when you press Build at lower detail. Tilted CTs are not supported yet for the model; the 2D images still work.
  • View → 3D only shows the model alone. The planes are hidden, not closed.
  • Visible pieces can be saved as one STL file, only on your click. The file is not password-protected, carries no patient name, id or date, and is not a surgical plan, template or guide. A regulatory read of this export is still needed before 0.1.0 ships that button.

Private library

  • A searchable local library: patient name, ID, date and modality. Names in Arabic and in Latin letters both work.
  • Studies can be sorted, opened, annotated and deleted. A disc’s SETUP.EXE or autorun.inf is never run. A study imported twice appears once.
  • The library is encrypted on disk. The key is held by the Windows account or the Mac Keychain. By default there is no app password.
  • On first start you save a recovery key on paper. It is the only way back in if the key file is lost or a PIN is forgotten.
  • Back up to a folder or USB stick, check a backup, and restore. A restore replaces the library on that computer. The backup holds only encrypted files.

Sharing, export, PDF and key images

  • Export can write an original DICOM copy, a de-identified copy, or a password-protected ZIP, only to the folder you choose.
  • The de-identified copy follows the DICOM Basic Profile for tags it can change. Study dates stay. Text burned into the pictures is not removed; the app asks you to confirm that you looked.
  • Save picture writes the image with its measurements and the calibration line. Including the patient name is off unless you tick it.
  • Share can make a PDF of a study, a key-image page, a scroll-through video or a picture grid. Shared files are anonymized by default and carry “For reference only, not for diagnosis”.
  • You can also print a page. Files are written only where you choose; nothing is left in a temporary folder.

Privacy, encryption and optional PIN

  • Works fully offline. No cloud, no accounts, no sync, no PACS connection, and no network calls in the app.
  • An optional PIN can be turned on in Settings → Security. With a PIN, a Lock button appears, and the library can lock itself after 5, 10 (the default), 15 or 30 idle minutes, or never. Idle lock waits for a running import or backup, and pauses in Present mode.
  • A PIN is walk-up protection only. It does not stop a program running as the signed-in user. Keep the operating system’s screen lock (and BitLocker on Windows) on as well.
  • Easy PINs such as 123456 are refused. After five wrong tries the app makes you wait. A forgotten PIN needs the recovery key; without it the library cannot be opened.
  • A problem report (Settings → Help) copies the version, the system and recent error codes. It holds no names, ids or file paths, and nothing is sent anywhere.

English and Arabic

  • The interface is available in English and Arabic. The language choice is remembered across restarts.
  • In Arabic the page layout is mirrored. Medical images, viewports, planes, the 3D model and on-image overlays stay left to right, so the patient’s left stays on the same side of the screen.
  • The Arabic text is a machine draft and still needs review by a native speaker. Some buttons may still appear in English.

Platforms

  • Windows 10 or 11, 64-bit (x64) Pre-release — a one-click installer. If Microsoft WebView2 is missing, the usual installer can download it (that step needs a network). An offline installer that includes WebView2 is planned, but is not in the current pre-release.
  • macOS on an Intel Mac Planned for 0.1.0 — a disk image is planned. It is not included in the v0.0.1 pre-release.
  • iPad In development — an iPad version is being built. It is not part of the public release on this site yet, and the iPad target is not on the main product line as released here.
  • Linux installers and ARM Windows builds are not in 0.1.0.

Download

Installers are published on the Releases page of this repository. Always download the installer and SHA256SUMS from that page, then check the checksum before you run the file.

The current pre-release is v0.0.1, an unsigned Windows installer: Nefertiti_0.0.1_x64-setup.exe and SHA256SUMS. Windows SmartScreen may warn because the build is unsigned; choose More info, then Run anyway. macOS and the offline WebView2 installer are not in this pre-release.

Version 0.1.0, the first signed public release, is not published yet. See the roadmap for what still has to happen first.

Check the download (SHA256SUMS)

SHA256SUMS lists one SHA-256 checksum per installer. The checksum of your file must match its line exactly. If it does not, delete the file and download it again. Do not run it.

Windows (PowerShell):

Get-FileHash .\Nefertiti_0.0.1_x64-setup.exe -Algorithm SHA256

Compare the Hash value with the line for that file in SHA256SUMS (case does not matter).

macOS (Terminal), in the folder with the downloads:

shasum -a 256 -c SHA256SUMS --ignore-missing

It prints OK next to each file that matches.

Roadmap

Towards 0.1.0

0.1.0 is the first signed public release. It is not out yet. Work that still stands in front of it includes:

  • Finishing and checking the 3D bone model (including hand checks on the intended PCs).
  • The slanted (oblique) MPR plane, which is required before 0.1.0. Curved MPR is not required.
  • Code signing: a signed Windows installer and a signed Intel Mac disk image, so the first-run security warning is no longer the expected path.
  • A regulatory read of the Export STL button before 0.1.0 ships that button.

A native-speaker review of the Arabic wording is also still needed. A lawyer’s review of the licence wording, and a check with the EDA and the SFDA, should be done before any sale or clinical claim, and before wide use in Egypt or Saudi Arabia.

Later, after 0.1.0

  • A clinic-network edition (an optional local network mode) is planned only after 0.1.0 is in real use. It would stay off until turned on.
  • There is no AI finding in the app today. Any later AI add-on would stay off by default and would need a regulatory review first. Reporting, cloud hosting of patient data, and image acquisition are not goals of this product.

Privacy

Patient data is meant to stay on the computer (and on a USB backup you make). The app works fully offline. It makes no network call and has no telemetry, analytics or update check. There is no account and no cloud.

The library is encrypted on disk. Plaintext images exist in memory only while the library is unlocked. Nothing decrypted is written to disk except when you explicitly export, share, print or save a picture — and then only to the folder, file or printer you pick.

Share is anonymized by default: name, ID, birth date and accession appear only when “Include patient details” is ticked, and that choice is never remembered. File names and file metadata never carry patient or study data. Images that may show patient details in their pixels start unticked; the app cannot find names written in pixels.

A problem report holds no names, ids or file paths, and nothing is sent anywhere. This site does not use third-party trackers or analytics.

These notes describe what the software is designed to do. They are not legal advice. Clinics are likely the data controllers under applicable privacy law and should check their own obligations, including Egypt’s Personal Data Protection Law and Saudi Arabia’s PDPL.

Frequently asked questions

Can I use Nefertiti to make a diagnosis?

No. Nefertiti is for reference only, not for diagnosis. It is not a medical device and has not been cleared or registered by any regulator. Do not use it as the basis for a diagnosis. Clinical decisions must be made with approved systems and by qualified people.

Does any patient data leave the computer?

Not by itself. The app works offline and makes no network calls. Copies leave the device only when you export, share, print or save a picture, and only to the destination you choose. Shared files are anonymized by default.

Is the source code public?

No. The source is proprietary and is not published. This site and this repository provide installers, the licence and third-party notices only.

Why does Windows warn me when I open the installer?

The v0.0.1 pre-release is unsigned. Windows SmartScreen may warn; choose More info, then Run anyway, after you have checked the SHA-256 checksum. Signed installers are planned for 0.1.0.

Is there a Mac or iPad download?

Not in the current pre-release. A signed disk image for Intel Macs is planned for 0.1.0. An iPad version is in development and is not published here yet.

Do I have to set a PIN?

No. On first start you can choose a PIN, or choose “This is my personal computer: no PIN”. You can change that later in Settings → Security. The files are encrypted on disk either way. If other people can sit at the computer, turn a PIN on.

Can the 3D bone model measure a volume?

No. The only numbers on the model are a distance, an angle, and the size of a piece’s box. It does not use AI. It is for reference only, not for diagnosis, and only CT can be built into a model. Tilted CTs are not supported for planes or the model yet; the 2D images still work.

Is there an Arabic interface?

Yes. You can switch the language to Arabic. The layout is mirrored; medical images are not. The Arabic text is a machine draft awaiting a native-speaker review, and some labels may still be in English.

What if the checksum does not match?

Delete the file and download it again from the official Releases page. Do not run a file whose checksum does not match SHA256SUMS.
